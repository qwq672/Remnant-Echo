## Q1 · 玩家进入新世界后应该怎么样？是否先展示剧情？是否出生在村庄附近？

### 问题拆解

| 子问题 | 项目方选项 |
|--------|------------|
| Q1-a | 是否先展示剧情（故事）再正式进入世界？ |
| Q1-b | 是否推荐出生在村庄附近（不是村庄中心）？ |

### 协作者建议

**Q1-a：不展示剧情前戏**

按 [原则 3 · 碎片化叙事](./00-planning-index.md#原则-3碎片化叙事)："玩家在探索中自行拼凑真相。不出现对话、过场、引导箭头。"

展示剧情前戏会违反碎片化叙事原则，破坏原版的"随机出生、自由探索"体验。原版 Minecraft 1.0+ 的开篇是"玩家出生，自由行动"，模组不应在玩家出生时强制弹窗叙事。

**替代方案**：玩家出生后自由探索，在自然接触原版结构（村庄/地牢/废弃矿井/沙漠神殿/丛林神庙/古迹废墟）时通过 loot 表追加的 `written_book` 触发叙事种子。详见 [`01-spawn-point-design.md`](./01-spawn-point-design.md) 方案 A。

**Q1-b：推荐出生在村庄附近，但不强制**

按 [`01-spawn-point-design.md`](./01-spawn-point-design.md) §5.2"不强制第一次会话触发"：玩家可能落在沙漠、海洋、雪原、丛林等无村庄群系，叙事第一环可能断裂——这是**可接受的**，因为符合碎片化叙事原则。

**推荐做法**：
- 不修改原版出生逻辑（保留随机性）
- 通过 loot 表扩展保证玩家在合理时间内（数小时内）自然触发叙事种子
- 若玩家落在村庄附近，可优先接触"考古棚/古碑"等模组附加物（方案 B+C，详见 [`01-spawn-point-design.md`](./01-spawn-point-design.md) §3）
- 若玩家不落在村庄附近，可在地牢/废弃矿井/沙漠神殿等任一含 loot 的原版结构中触发

**结论**：模组**不干预出生逻辑**，但通过多种原版结构的 loot 表追加笔记条目，保证叙事种子在合理时间内自然埋下。

## Q2 · 开场之后的第一个任务（不进入村庄）？

### 问题拆解

项目方明确："不包含玩家进入村庄"——即在玩家尚未接触村庄的早期阶段，模组应给玩家的第一个"任务"是什么？

### 协作者建议

**核心立场：模组不主动布置"任务"**

按 [原则 3 · 碎片化叙事](./00-planning-index.md#原则-3碎片化叙事)："叙事不是任务，是探索的副产品。"

模组**不主动布置任务**——玩家进入世界后是"自由探索"状态，与原版 Minecraft 一致。玩家可挖矿、采集、建造、生存，模组不干预。

**叙事种子的自然触发**：

玩家在自由探索中，会自然接触以下任一原版结构，触发模组叙事种子：

| 原版结构 | 触发方式 | 笔记编号 | 叙事意义 |
|----------|----------|----------|----------|
| 地牢（怪物室） | 箱子追加 12% `written_book` | #5 | 监禁/储存记录 |
| 废弃矿井 | 矿车追加 8% `written_book` | #4 | 劳工日志 |
| 沙漠神殿 | 箱子追加 10% `written_book` | #2 | 祭祀记录 |
| 丛林神庙 | 箱子追加 10% `written_book` | #3 | 红石记录 |
| 古迹废墟 | 考古陶罐追加 8% `written_book` | #15 | 撤退者记录 |

**推荐做法**：模组**不主动告诉玩家"第一个任务"**，让玩家自由探索。当玩家拾取到任一笔记时，通过 advancement 触发 tellraw："线索书第 0 章已解锁"——这才是模组的第一个"叙事介入点"，而非任务。

**与原版兼容性**：玩家若完全不接触含 loot 的结构，叙事种子可能延迟触发——这是可接受的，符合碎片化叙事原则。

## Q3 · 末地顺序：原版打龙 vs 剧情先末地城？

### 问题拆解

原版玩家击败末影龙后通常直接走回归传送门，不会探索末地城。若模组要求"先末地城再打龙"，会破坏原版节奏。

### 协作者建议

**核心立场：保持原版"先打龙"默认路径，不强制顺序**

按 [`06-cognitive-lock-mechanism.md`](./06-cognitive-lock-mechanism.md) 已确立的认知锁机制：未达标玩家进入末地时显示"黑雾反噬"提示，但**不强制阻止**玩家。

**推荐做法**：

1. **认知锁机制**：通过原版 `advancement` 触发器检测玩家是否解锁了关键叙事（笔记 #1-#14），若未达标则显示 tellraw："你还没有准备好。回去看看那些遗迹。"——但玩家仍可自由进入末地。

2. **折跃门作为物理引导**：玩家击败末影龙后，原版会激活末地折跃门（通往外岛），这是原版机制，模组可利用：
   - 击败末影龙 → 触发守门人真相 tellraw（[`07-boss-narrative-binding`](./07-boss-narrative-binding.md)）
   - 玩家若直接走回归传送门 → 回主世界，可在后续重入末地时探索末地城
   - 玩家若通过折跃门 → 自然引导至末地城，触发笔记 #23-#26 + 真结局

3. **0 号唱片的合成自然引导**：0 号唱片的合成需要 22 张原版唱片（含末地城的 ward 唱片），玩家若要达成真结局，**必须**去末地城取 ward 唱片——这是叙事对探索的"软引导"。

**结论**：不强制顺序，但通过原版机制（折跃门）+ 合成需求（0 号唱片）软引导玩家自然完成"打龙 → 折跃 → 末地城 → 真结局"路径。

## Q4 · 主线剧情收尾？整个游戏收尾？

### 协作者建议

**主线剧情收尾：0 号唱片 + M. 遗言**

按 [`20-end-narrative.md`](./20-end-narrative.md) §14 真结局叙事：
- 玩家合成 0 号唱片（22 张原版唱片 + 下界之星）
- 播放 0 号唱片 → 听到 M. 遗言全文
- M. 揭晓 C.=M. 同人真相
- 玩家从"局外人"觉醒为"继承者"
- "这个世界，现在交给你了"

**整个游戏收尾：开放式结尾**

按 [原则 2 · 贴合原版留白逻辑](./00-planning-index.md#原则-2贴合原版留白逻辑)：模组不强行结束游戏。玩家完成真结局后，世界继续存在——玩家作为继承者继续探索。

**收尾后的可选彩蛋**（v1.0 后考虑）：
- 末影人偶尔对玩家点头致意（暗示"被遗忘的士兵"已解脱）
- 村庄图书管理员会偶尔出售"先民手稿"（普通 `written_book`，纯装饰）
- 玩家击败凋灵/监守者时触发额外对比文本（"先民的灾变余响，在你手中结束"）

**结论**：主线以 0 号唱片+M. 遗言收尾（叙事高潮）；整个游戏以"玩家作为继承者继续探索"开放式结尾（不强行结束）。

## Q7 · 模组需要哪些工作？占比？

### 协作者建议

按 [`17-mod-introduction-copy.md`](./17-mod-introduction-copy.md) 特性清单 + [`10-custom-items-registry.md`](./10-custom-items-registry.md) L3 自定义清单，估算各工作占比：

| 工作类型 | 占比 | 具体内容 | 工作量评估 |
|----------|------|----------|------------|
| **文学** | **50%** | 22 张笔记内容设计 + End Poem 重新解读 + M. 遗言全文 + advancement 提示文本 + tellraw 消息 + Patchouli 章节内容 + 多语言翻译（zh_cn+en_us+其他 6 语言） | 22 张笔记 × 200-300 字 + 8 语言 × 50+ 字符串 = 高工作量 |
| **代码** | **30%** | Fabric/NeoForge 框架搭建 + loot 表 JSON 修改 + advancement JSON 配置 + tellraw function + Patchouli 软依赖集成 + 5 个 L3 自定义物品注册 + GitHub Action 自动同步（v0.5+） + 多人服务器兼容测试 | 中等工作量，但涉及多系统集成 |
| **美术** | **15%** | 5 个 L3 自定义物品纹理（残破笔记/线索书/0 号唱片/先民储藏室/残破石碑） + Patchouli 书界面美化（可选） + 思维导图（已部分完成） | 低工作量，因 L3 仅 5 项 |
| **音乐** | **5%** | **不新增音乐文件**——通过监听玩家位置/事件播放对应原版曲目（C418/Lena Raine），仅配置播放时机 JSON | 极低工作量 |

### 详细说明

**文学是核心（50%）**：
- 模组的"灵魂"是 22 张笔记+End Poem 解读+M. 遗言
- 这些文本是不可省略的核心资产，且需多语言翻译（8 语言）
- 项目方亲笔 zh_cn + en_us 互校，社区贡献其他语言

**代码占 30%**：
- 主要是 loot 表 JSON 修改（L1，约占代码工作 60%）
- advancement JSON 配置（L1，约占代码工作 20%）
- 5 个 L3 自定义物品的 Item 注册（约占代码工作 15%）
- Patchouli 软依赖集成（约占代码工作 5%）

**美术占 15%**：
- 5 个 L3 自定义物品的纹理（基于原版纹理修改）
- 不新增材质包，不新增粒子效果
- Patchouli 书界面可选美化（v0.5 后）

**音乐占 5%**：
- **不新增音乐文件**（按 [原则 0 · L1 优先](./00-planning-index.md#原则-0优先原版实在没辙才自定义且必须与原版有关)）
- 仅配置原版音乐的播放时机（通过 `advancement` reward function 触发 `/playsound` 命令）

**结论**：模组以文学为核心（50%），代码次之（30%），美术与音乐合计 20%。这是"叙事模组"的合理占比，与 L1/L2/L3 原则一致——优先原版，自定义最少。

| **Echo** | 回声/余响 | 简洁、易记、跨语言；与"声音"主题契合（22 张唱片+0 号唱片）；与"先民文明的余响"叙事主题契合；Minecraft 模组生态中无冲突 | 含义略抽象 |
| Remnant | 遗族/残余 | 与"先民后裔"叙事契合；中英一致 | 与"Last Remnant"等游戏名接近 |
| Pale | 苍白（关联苍白花园） | 与苍白之悔叙事契合 | 单词过于通用，搜索冲突多 |
| Sonder | 过客感 | 与"玩家是局外人"叙事契合 | 含义过于小众，玩家陌生 |

### 协作者推荐：Echo

**推荐理由**：
1. **叙事契合**：模组核心叙事是"先民文明的余响"——22 张唱片是声音遗迹，End Poem 是 M. 的回响，0 号唱片是真结局的最终回响
2. **多语言一致**：Echo 在中英文中含义一致（"回声/余响"），其他语言也容易理解
3. **Minecraft 模组生态无冲突**：截至 2026 年，CurseForge/Modrinth 上无名为 "Echo" 的活跃 Minecraft 叙事模组
4. **副标题建议**：`Echo · A Minecraft Lore Mod`（按 17 §2 命名格式建议）

**最终决策权**：项目方审核。

**协作者备选方案**（若 Echo 不通过）：
- Remnant · A Minecraft Lore Mod（次选）
- Echoes · A Minecraft Lore Mod（复数形式备选）

## Q10 · 整体封装 vs 分前后置？内置光影？规则树？

### 问题拆解

| 子问题 | 项目方选项 |
|--------|------------|
| Q10-a | 直接封装成一个模组，还是分前置+后置？ |
| Q10-b | 是否增加内置光影为低端设备添加沉浸感？ |
| Q10-c | 是否通过额外的规则树让大部分生物充满生动并变聪明？ |

### 协作者建议

**Q10-a：直接封装为单一模组**

按 [`17-mod-introduction-copy.md`](./17-mod-introduction-copy.md) §6.4 已明确："独立模组，不整合其他模组。"

**推荐做法**：
- 单一 Fabric/NeoForge 模组 jar 包
- 不分前置+后置——模组规模小（5 个 L3 自定义+若干 loot 表 JSON+advancement JSON），无需拆分
- 可选软依赖：Patchouli（缺失时降级为 tellraw）、JEI（仅合成查询）

**Q10-b：不增加内置光影**

按 [原则 0 · 永远禁止清单](./00-planning-index.md#l3-自定义的永远禁止清单)：
- 内置光影本质是"新机制"，违反 L1 优先原则
- 低端设备玩家可自行安装 OptiFine / Iris Shaders 等社区光影
- 模组**不内置光影**，避免与现有光影模组冲突

**替代方案**：通过原版 `particle` 命令在关键场景（认知锁未达标、远古城市、苍白花园、末地城）显示氛围粒子，提升沉浸感。这是 L1 实现，不新增任何视觉机制。

**Q10-c：不通过规则树改变生物 AI**

按 [原则 0 · 永远禁止清单](./00-planning-index.md#l3-自定义的永远禁止清单)：
- "改变原版生物 AI/掉落" 明确禁止
- "新驯服/骑乘机制" 明确禁止
- 规则树让生物"变聪明"需要修改生物 AI，违反原则 0

**替代方案**：通过 `advancement` 触发 `tellraw`，在玩家首次接触特定生物时显示叙事解读：
- 玩家首次击杀骷髅 → tellraw："执行最后命令的射手，终于解脱。"
- 玩家首次遭遇末影人 → tellraw："他们不是怪物。是被遗忘的士兵。"
- 玩家首次进入村庄 → tellraw："村民保留了古法，但失忆了。"

这是 L1 实现，不修改任何原版生物 AI。

**结论**：
- 单一模组封装（不分前置后置）
- 不内置光影（违反原则 0）
- 不通过规则树改变生物 AI（违反原则 0）
- 通过原版 `particle` + `tellraw` 提升沉浸感（L1 实现）

## Q11 · 参考官方衍生游戏？

### 协作者建议

按 [原则 5 · 基于官方衍生作品可参考，但以原版为准](./00-planning-index.md#原则-5基于官方衍生作品可参考但以原版为准) + 已有 [`14-official-derivatives/`](../14-official-derivatives/) 章节汇编：

**Minecraft Legends（传说）**：
- 设定"先民文明曾与下界'猪灵帝国'交战" → 模组可作凋灵之灾前奏的支线彩蛋（不作主线必经）
- 设定"天启骑士 Action/Foresight/Knowledge/Hope" → 模组可解读为先民文明的四位领袖（对应四大研究领域）
- 设定"灾厄村民曾为抵御猪灵入侵拿起武器" → 模组采纳为灾厄村民分支叙事（已记录于 [`15-community-lore/03`](../15-community-lore/03-reddit-forum-theories.md) §11）

**Minecraft Dungeons（地下城）**：
- 设定"奇厄教主从灾厄村民分支崛起" → 模组可作灾厄村民现代继承者彩蛋
- 设定"末影之心作为终局 Boss" → 模组可参考但**不引入**（避免与模组末影龙守门人叙事冲突）
- 设定"穹顶之岛/下界荒野/末地荒野等新区域" → **不采纳**（违反"不新增维度"原则）

### 协作者推荐采纳范围

| 衍生作设定 | 模组采纳程度 | 引用方式 |
|------------|--------------|----------|
| Minecraft Legends 灾厄村民起源 | ✅ 完全采纳 | [`18-overworld-narrative`](./18-overworld-narrative.md) 已引用 |
| Minecraft Legends 猪灵入侵主世界 | ⚠️ 不作主线事件 | 仅作叙事文本中的历史回顾，不引入新事件机制 |
| Minecraft Legends 天启骑士 | ✅ 完全采纳（解读） | 解读为先民四位领袖，对应四大研究领域 |
| Minecraft Dungeons 奇厄教主 | ✅ 部分采纳（彩蛋） | 作为灾厄村民现代继承者彩蛋，v0.5 后考虑 |
| Minecraft Dungeons 末影之心 | ❌ 不采纳 | 与末影龙守门人叙事冲突 |
| Minecraft Dungeons 新区域 | ❌ 不采纳 | 违反"不新增维度"原则 |

**结论**：参考 Minecraft Legends 设定灾厄村民起源与天启骑士解读；Minecraft Dungeons 仅作彩蛋参考，不引入新 Boss/新维度。所有衍生作设定仅作叙事辅助，以原版为准。
