## 3. Q8 模组命名 · 重名查询与组合名建议

### 3.1 重名查询结果（2026-09-21 真实搜索）

通过 `z-ai function web_search` 进行 3 次重名查询：

#### Echo 查询

- **搜索关键词**：`Echo Minecraft mod CurseForge Modrinth lore narrative`
- **结果数**：8 条
- **重名情况**：**无完全重名** ✅
- **结果摘要**：
  - Modrinth 上有 "Better Lore"（叙事扩展类，非同名）
  - CurseForge 上有 "Storify - Story Mode Sound Overhaul"（音效包，非同名）
  - **结论：Echo 在 Minecraft 模组生态无重名冲突，可自由使用**

#### Remnant 查询

- **搜索关键词**：`Remnant Minecraft mod CurseForge Modrinth story`
- **结果数**：8 条
- **重名情况**：**有部分重名** ⚠️
- **关键发现**：
  - **CurseForge 上已有 "Remnant Bosses"**（curseforge.com/minecraft/mc-mods/remnant-bosses），描述为"Born from the depths of the underworld, Remnants introduces cinematic boss encounters, dangerous undead creatures, and fast-paced combat"
  - YouTube 有 "Cataclysm Pt 3: Ancient Remnant" 视频（与 L_Ender's Cataclysm 模组关联）
- **结论**：Remnant 单独使用会与 "Remnant Bosses" 产生混淆，建议避免单独使用

#### Pale 查询

- **搜索关键词**：`Pale Minecraft mod CurseForge narrative`
- **结果数**：1 条
- **重名情况**：**部分相关** ⚠️
- **关键发现**：CurseForge 上有 "Hendrix's Better Pale Garden"（苍白花园增强）
- **结论**：Pale 单独使用过于通用，且与苍白花园相关模组产生混淆

### 3.2 组合名候选

基于重名查询结果（Echo 无重名，Remnant 有重名），协作者推荐以下组合名候选：

| 候选名 | 类型 | 优点 | 缺点 | 推荐度 |
|--------|------|------|------|--------|
| **Echo** | 单名 | 无重名；简洁；跨语言；与"声音遗迹"叙事契合 | 含义略抽象 | ★★★★★ 首推 |
| **Echo · A Minecraft Lore Mod** | 单名+副标题 | 标准命名格式；明确类型 | 副标题略冗长 | ★★★★ 备选 |
| **Echoes of the Ancients** | 组合名 | 与"古代建造者"+"回声"双关；叙事契合 | 名称略长 | ★★★ 次推 |
| **Remnant Echo** | 组合名（Remnant 副名） | 避开 Remnant Bosses 重名；保留 Remnant 含义 | 略冗长 | ★★★ 次推 |
| **The Pale Echo** | 组合名 | 与苍白花园关联；视觉叙事 | 与"Better Pale Garden"部分相关 | ★★ 不推 |
| **Sonder: An Echo** | 组合名 | 玩家局外人感+回声 | 含义小众 | ★ 不推 |

### 3.3 协作者建议

**首推：Echo**

理由：
1. **无重名冲突**（2026-09-21 搜索确认）
2. **叙事契合**：模组核心叙事是"先民文明的余响"——22 张唱片是声音遗迹，End Poem 是 M. 的回响，0 号唱片是真结局的最终回响
3. **多语言一致**：Echo 在中英文中含义一致（"回声/余响"），其他语言也容易理解
4. **简洁易记**：单音节，玩家容易记忆与传播

**备选：Echoes of the Ancients**（若项目方倾向组合名）

理由：
1. **组合名避开单名重名风险**（虽然 Echo 无重名，但组合名更稳妥）
2. **"of the Ancients"** 直接关联模组的"古代建造者"叙事
3. **副标题明确**：玩家看到名字就能知道模组主题

**最终决策权**：项目方审核。

## 4. Q9 配乐重新评估 · L1/L2/L3 三级配乐策略

### 4.1 项目方意见

项目方回复："Q9 我想着额外配乐的原因是原版存的音乐一定程度上都已经用过导致直接用可能有点单调或者不符场景，所以说我想着能不能借用类似风格的音乐或自创配乐使其补全部分场景下的使用。"

### 4.2 协作者重新评估

项目方提出的"原版音乐单调/不符场景"问题确实存在。例如：
- 远古城市已使用原版 5 号唱片，但 5 号唱片本身是 Lena Raine 为监守者设计的"觉醒"主题，无法承载模组"幽匿之厄"的悲剧深度
- 苍白花园已使用 Relic 唱片，但 Relic 是 Aaron Cherof 为考古发现设计的"残响"主题，无法承载模组"苍白之悔"的颓废感
- 真结局的 0 号唱片若仅使用原版 13 号唱片的纹理，无法承载 M. 遗言的庄重感

按 [原则 0 · L1/L2/L3 判定](./00-planning-index.md#原则-0优先原版实在没辙才自定义且必须与原版有关)，本协作者重新评估配乐策略如下：

### 4.3 三级配乐策略（修订版）

#### L1 · 优先原版音乐（~70%）

继续使用原版音乐作为主基调，按 [`22-design-questions-answers.md`](./22-design-questions-answers.md) §Q9 已配置的 18+ 场景执行：
- 出生：`cat`
- 沙漠神殿：`mellohi`
- 远古城市：`5`
- 苍白花园：`Relic`
- 等等

**适用场景**：所有原版遗迹、所有原版 Boss 战、所有日常探索阶段。

#### L2 · 原版音乐组合（~15%）

通过原版 `/playsound` 命令的组合与时间控制，实现"原版音乐的二次创作"：

| 组合方式 | 实现方法 | 适用场景 |
|----------|----------|----------|
| 多重 playsound | 同时播放多个原版音轨，叠加形成"和弦"效果 | 重大叙事节点（如拾取笔记 #14 灵魂能量研究员手记时，叠加 `5`+`otherside` 形成"幽厄"效果） |
| 调速播放 | 通过 `/playsound` 的 `pitch` 参数调整原版音轨速度 | 怪物追击场景（如监守者追击时，将 `5` 调速至 0.8 形成压迫感） |
| 调音量 | 通过 `/playsound` 的 `volume` 参数控制远近 | 远古城市深处的"幽匿回响"效果 |
| 间歇播放 | 通过 function 定时播放短片段 | 灾厄村民叙事的"警报"效果 |

**适用场景**：原版音乐无法完整承载的场景，但可通过组合实现。

#### L3 · 自创配乐（~15%，需严格论证）

仅在 L1+L2 均无法承载叙事时，允许自创少量补全配乐。**每首自创配乐必须通过 L3 论证**：

##### L3 自创配乐的必要性论证标准

| 必要性条件 | 论证要求 |
|------------|----------|
| L1 不可行 | 原版音乐中确无任何曲目能承载该场景的叙事深度（需列举所有原版曲目的尝试与失败原因） |
| L2 不可行 | 原版音乐的组合（多重/调速/调音量/间歇）也无法承载该场景 |
| 关联性论证 | 自创配乐必须满足至少 2 项关联标准（见下表） |

##### L3 自创配乐的关联性标准

| 关联维度 | 说明 | 示例 |
|----------|------|------|
| **风格关联** | 配乐风格基于原版 C418/Lena Raine/Aaron Cherof 的风格衍生 | 自创"苍白之悔"配乐基于 Aaron Cherof 的 Relic 风格衍生 |
| **乐器关联** | 使用原版已有的乐器或音色 | 自创配乐使用钢琴/合成器/弦乐（C418 标志性乐器） |
| **节奏关联** | 节奏与原版某曲目相近 | 自创"幽匿之厄"配乐的节奏与原版 5 号唱片相近 |
| **退化关联** | 失去模组时配乐自动停止播放，玩家不会"听到缺失" | 自创配乐通过模组资源包加载，模组卸载后原版音乐仍正常播放 |
| **场景关联** | 配乐仅在该场景触发，不替换原版音乐 | 自创"真结局 0 号唱片"配乐仅在玩家合成 0 号唱片后触发 |

##### L3 自创配乐候选清单（待项目方审核）

基于 Q9 重新评估，以下场景可考虑 L3 自创配乐：

| 场景 | L3 自创配乐名 | 必要性论证 | 关联性论证 | 优先级 |
|------|--------------|------------|------------|--------|
| **真结局·0 号唱片播放** | `M.'s Farewell`（M. 的告别） | L1：原版 13 号唱片是 C418 的"洞穴探索录音"，无法承载 M. 遗言的庄重感；L2：调速/组合也无法承载文字叙事的重量 | 风格关联（基于 C418 ambient 风格）+ 乐器关联（钢琴+合成器）+ 退化关联（模组卸载后无声音，玩家仍可阅读 tellraw 遗言） | ★★★★★ 首要 |
| **苍白花园深处·嘎枝激活** | `Pale Regret`（苍白之悔） | L1：Relic 唱片是 Aaron Cherof 的"考古残响"，无法承载生命树脂实验失控的颓废感；L2：调速/组合也无法表达"白化侵蚀"的视觉听觉双重感 | 风格关联（基于 Aaron Cherof Relic 风格）+ 场景关联（仅嘎枝激活时触发） | ★★★ 次要 |
| **远古城市深处·监守者追击** | `Sculk Echo`（幽匿回响） | L1：5 号唱片是 Lena Raine 的"监守者觉醒"，但仅适合"觉醒"瞬间，无法承载"追击"的紧张感；L2：调速至 0.8 可承载紧张感但音质失真 | 风格关联（基于 Lena Raine 5 号唱片风格）+ 节奏关联（与 5 号唱片相近）+ 场景关联（仅监守者追击时触发） | ★★★ 次要 |
| **凋灵召唤·灾变复现** | `Withering Wave`（凋零之波） | L1：原版凋灵战 BGM 是 Boss 战音乐，无法承载"先民复现灾变"的叙事深度；L2：调速也无法承载 | 风格关联（基于 C418 Nether 风格）+ 场景关联（仅玩家召唤凋灵时触发） | ★★ 可选 |
| **末地城图书馆·笔记 #23 拾取** | `Colonial Echo`（殖民回响） | L1：原版 11 号唱片是 C418 的"最后逃亡录音"，无法承载"殖民军初到末地"的庄重感；L2：调速/组合也无法承载 | 风格关联（基于 C418 11 号唱片风格）+ 乐器关联（钢琴+磁带噪音）+ 场景关联（仅笔记 #23 拾取时触发） | ★★ 可选 |

##### L3 自创配乐的退化方案

按 [原则 0 · 退化关联](./00-planning-index.md#l3-自定义的关联性标准) 标准，所有 L3 自创配乐必须提供退化方案：

```
模组卸载时的行为：
1. 自创配乐文件不被加载（资源包未注册）
2. 玩家在该场景下听到的是"无音乐"（仅有原版环境音）
3. 玩家不会"听到缺失"——因为模组的 tellraw 仍可正常显示叙事文本
4. 真结局的 0 号唱片在模组卸载后退化为原版 13 号唱片，仍可正常播放
5. 配乐是"叙事增强"而非"叙事必需"——缺失不影响主线推进
```

##### L3 自创配乐的工作量

按 [`22-design-questions-answers.md`](./22-design-questions-answers.md) §Q7 已估算音乐占比 5%（仅配置原版播放时机）。若加入 L3 自创配乐，工作量增加：

| 自创配乐数量 | 工作量增量 | 总音乐占比 |
|--------------|------------|------------|
| 0 首（纯 L1+L2） | +0% | 5% |
| 1 首（仅 0 号唱片） | +3% | 8% |
| 3 首（0 号+苍白+幽匿） | +8% | 13% |
| 5 首（全部候选） | +12% | 17% |

**协作者建议**：v0.1 ~ v0.5 仅实施 L1+L2（无自创配乐，音乐占比 5%）；v0.6 真结局开发时启动 L3 自创配乐"0 号唱片告别曲"（音乐占比 8%）；v0.9 ~ v1.0 视项目方意愿决定是否补全其他 4 首。

### 4.4 社区先例支持

本协作者通过真实搜索发现，Minecraft 模组社区已有自创配乐先例：

- **LOTR Mod**：有"Music Packs"功能，允许玩家自定义生物群系音乐（lotrminecraftmod.fandom.com）
- **Story Mode OST**：Modrinth 上有完整资源包替换所有 Minecraft 音乐（modrinth.com）
- **Minecraft: Story Mode (Original Soundtrack)**：由 Antimo & Welles 创作的官方衍生 OST（antimo.bandcamp.com）

**结论**：Minecraft 模组社区已有自创配乐先例，L3 自创配乐不违反社区惯例，但需通过 L3 论证与退化方案。

## 5. Q11 衍生作采纳范围放宽

项目方回复："允许随便（不管进不进主线）"——意味着 Minecraft Legends 与 Minecraft Dungeons 的内容可以随意采纳，不限于主线必经与否。

### 5.1 修订后的衍生作采纳范围

基于项目方意见，将 [`22-design-questions-answers.md`](./22-design-questions-answers.md) §Q11 的采纳范围放宽：

| 衍生作设定 | 原建议 | 修订后建议 |
|------------|--------|------------|
| Minecraft Legends 灾厄村民起源 | ✅ 完全采纳 | ✅ 完全采纳（不变） |
| Minecraft Legends 猪灵入侵主世界 | ⚠️ 不作主线事件 | ✅ **可采纳为支线事件**（不作主线必经，但可作为彩蛋或可选 raid 变体） |
| Minecraft Legends 天启骑士 | ✅ 完全采纳（解读） | ✅ 完全采纳（解读为先民四领袖） |
| Minecraft Dungeons 奇厄教主 | ✅ 部分采纳（彩蛋） | ✅ **可作更深采纳**（可作为灾厄村民分支的现代领袖，出现在林地府邸彩蛋中） |
| Minecraft Dungeons 末影之心 | ❌ 不采纳 | ⚠️ **可考虑作为彩蛋 Boss**（不作主线，但作为可选挑战——若项目方有意，需 L3 论证为末影龙的 NBT 变体） |
| Minecraft Dungeons 新区域（穹顶之岛/下界荒野/末地荒野） | ❌ 不采纳 | ❌ **仍不采纳**（违反"不新增维度"原则，即使项目方允许，也违反原则 0 的"永远禁止"清单） |

### 5.2 严格约束

即使项目方"允许随便"，仍需遵守以下约束：

1. **不新增维度**：Minecraft Dungeons 的"穹顶之岛"等新区域仍不可采纳（违反原则 0 "永远禁止"清单）
2. **不新增 Boss 实体**：Minecraft Dungeons 的"末影之心"若采纳，必须作为原版 Boss 的 NBT 变体（如末影龙的 Phase 行为变体），不可作为新实体
3. **不修改原版机制**：Minecraft Legends 的"猪灵入侵主世界"若采纳，必须通过原版 raid 机制的变体实现，不可新增机制
4. **L3 论证**：所有采纳的衍生作内容若涉及 L3 自定义，仍需通过 L3 论证与退化方案

#### 6.2.1 当前规划的缺口

#### 6.2.3 支线叙事文档的内容标准

每份支线叙事文档应包含：

| 章节 | 内容 |
|------|------|
| 1. 目的 | 该生物/场景在模组叙事中的定位 |
| 2. 原版依据 | 原版对该生物/场景的已有设定（minecraft.wiki/minecraft.net 引用） |
| 3. 社区理论 | 知名社区对该生物/场景的理论（引用 `15-community-lore/`） |
| 4. 模组解读 | 模组对该生物/场景的叙事解读 |
| 5. 关联笔记 | 与该生物/场景相关的笔记编号（如有） |
| 6. advancement 触发 | 玩家首次接触该生物/场景时触发的 advancement 与 tellraw 文本 |
| 7. 配乐建议 | 该生物/场景的配乐建议（L1/L2/L3） |
| 8. L1/L2/L3 判定 | 该生物/场景叙事的 L 等级判定 |
| 9. 修订历史 | 文档修订记录 |

#### 6.2.4 与已有规划文档的关系

- `lore-stories/` 与 18/19/20 是**互补关系**：18/19/20 按维度汇总，`lore-stories/` 按生物/场景细化
- `lore-stories/` 不重复 18/19/20 的内容，而是聚焦于"单个生物/场景的深度叙事"
- 18/19/20 引用 `lore-stories/` 的具体生物/场景文档作为细化参考

#### 6.2.6 工作量估算

按每份支线叙事 500-800 字估算：
- 12 份生物支线 + 11 份场景支线 = **23 份文档**
- 每份约 500-800 字 × 23 = **11,500 - 18,400 字**
- 占文学工作量的 **15-20%**（文学总占比 50% 的一部分）

**协作者结论**：推荐创建 `lore-stories/` 章节，按生物/场景分 23 份文档。可在 v0.1 开发启动后逐步完成，不阻塞当前资料阶段。
