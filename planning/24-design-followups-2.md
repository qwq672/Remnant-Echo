## 2. 模组命名最终确认

### 2.1 项目方决定

项目方回复："另外，名字我差不多确定了，用 **remnant echo**"

### 2.2 协作者处理

**正式命名**：`Remnant Echo`（首字母大写格式）

**命名含义**：
- **Remnant**（遗族/残余）：先民后裔（村民、猪灵、末影人、灾厄村民、骷髅等）的统称

- 在 Minecraft 模组生态无重名冲突 ✅

**后续行动**：

## 3. 模组定位扩展 · 补齐世界观 + 电影感叙事

### 3.1 项目方澄清

项目方回复："另外，这个模组其实不止是叙事，还是相当于把原版的世界观全部补齐了，差不多就是补齐整个世界观的拼图，并且我准备考虑稍微像电影一样，当然，整个剧情过程也不要太无聊了"

### 3.2 协作者重新评估定位

**原定位**（按 [`17-mod-introduction-copy.md`](./17-mod-introduction-copy.md)）：
> 基于 Minecraft 原版碎片化线索构建的叙事模组

**扩展后定位**：
> Minecraft 原版世界观补齐模组——通过对原版留白的合理串联，把零散的碎片化线索拼凑成完整的远古先民文明兴衰史诗，并以电影化的叙事节奏呈现

### 3.3 "补齐世界观"与"碎片化叙事"的关系调和

项目方提出"补齐整个世界观"似乎与 [原则 2 · 贴合原版留白逻辑](./00-planning-index.md#原则-2贴合原版留白逻辑) 的"留白处继续留白"有矛盾。协作者作如下调和：

| 维度 | "补齐世界观" | "碎片化叙事" |
|------|--------------|--------------|
| **开发者视角** | 模组内部有完整的世界观文档（六大纪元、四大研究领域、四色光谱、12 位角色网络） | ✅ 这是"补齐"——开发者用文档把原版留白串联成完整体系 |
| **玩家视角** | 玩家通过 22 张笔记+End Poem+0 号唱片逐步发现真相 | ✅ 这是"碎片化"——玩家不是被一次性告知，而是通过探索拼凑 |
| **关键区别** | 开发者补齐 ≠ 玩家被填鸭 | 模组内部"知道"完整真相，但玩家通过探索"发现"真相 |

**结论**：模组定位扩展为"补齐整个原版世界观"，但**通过碎片化叙事方式呈现**——开发者补齐≠玩家被填鸭。这与原则 2 不冲突，反而强化原则 2 的"留白处继续留白"（对玩家而言，留白处仍留白，需玩家自行探索）。

### 3.4 "像电影一样"与原则 3 的关系调和

项目方提出"稍微像电影一样"，似乎与 [原则 3 · 碎片化叙事](./00-planning-index.md#原则-3碎片化叙事) 的"不出现对话/过场/引导箭头"有矛盾。协作者作如下调和：

| 维度 | "像电影一样" | "碎片化叙事" |
|------|--------------|--------------|
| **视觉听觉** | 通过原版 particle + /playsound + tellraw 营造电影化的氛围（黑雾粒子、配乐时机、叙事文本同步显示） | ✅ 不冲突——电影感通过环境氛围营造，非过场播片 |
| **叙事节奏** | 通过 advancement 触发 tellraw 的时机控制，让叙事在关键时刻爆发（如击败末影龙后立即显示守门人真相） | ✅ 不冲突——关键节点的叙事爆发≠过场 |
| **玩家控制** | 玩家仍可自由控制视角与行动，不被强制锁定 | ✅ 不冲突——电影化氛围≠剥夺控制 |
| **关键约束** | ❌ 不预渲染视频、不录制回放、不强制播片 | 这是原则 3 的底线 |

**结论**：模组采用"电影化碎片叙事"——通过原版 particle + /playsound + tellraw 的精妙时机控制，在玩家自由探索中爆发关键叙事，营造电影感而不剥夺玩家控制。

### 3.5 "剧情过程不要太无聊"的实现策略

按 [`03-player-journey-map.md`](./03-player-journey-map.md) 十阶段路径，每个阶段需有"非叙事性"的玩法支撑：

| 阶段 | 叙事内容 | 玩法支撑（避免无聊） |
|------|----------|---------------------|
| 1 种子埋下 | 拾取笔记 #1 | 玩家自由探索+生存建造 |
| 2 主世界考古 | 笔记 #2-#6, #15-#18 | 5 个原版遗迹的探索+解谜（沙漠神殿 TNT 陷阱/丛林神庙绊线/废弃矿井矿车） |
| 3 下界初探 | 笔记 #11-#12, #19-#22 | 下界生存+猪灵以物易物+躲避恶魂 |
| 4 下界深处 | 凋灵之灾余波 | 凋灵骷髅头颅收集+凋灵召唤战 |
| 5 远古城市 | 笔记 #14 + 监守者叙事 | 潜行避开监守者+幽匿感知机制 |
| 6 苍白花园 | 笔记 #18 + 嘎枝叙事 | 嘎枝之心破坏+苍白橡木采集 |
| 7 进入末地 | 击败末影龙 + End Poem | 末影龙战+末地水晶破坏+末影人对抗 |
| 8 末地城探索 | 笔记 #23-#24 | 末地城探索+潜影贝战斗+鞘翅获取 |
| 9 末影人记忆 | 笔记 #25 | 终界岛探索+末影人对抗 |
| 10 真结局 | 笔记 #26 + 0 号唱片 | 唱片收集+合成+播放 |

**关键策略**：每个叙事节点都伴随原版玩法的挑战，玩家不会"只读文本"。

## 4. Q13 · 除了末影龙外，是否有主线剧情需要击败 Boss？

### 4.1 协作者回答

按 [`07-boss-narrative-binding.md`](./07-boss-narrative-binding.md) 已确立的 Boss 叙事体系，主线需击败 3 个原版 Boss：

| Boss | 击杀方式 | 叙事主题 | 玩家阶段 | 必要性 |
|------|----------|----------|----------|--------|
| **凋灵** | 玩家主动召唤（用凋灵骷髅头颅+灵魂沙） | 灾变的余响——玩家重现了先民的凋灵召唤 | 阶段 4 下界深处 | ✅ 主线必经 |
| **监守者** | 玩家意外遭遇（在远古城市触发） | 幽匿之厄的悲剧——科研贵族灵魂聚合体 | 阶段 5 远古城市 | ✅ 主线必经 |
| **末影龙** | 玩家主动挑战（要塞+末地传送门） | 守门人真相——先民制造的最终守门人 | 阶段 7 进入末地 | ✅ 主线必经 |

### 4.2 可选支线 Boss

| Boss | 触发方式 | 叙事意义 | 是否必经 |
|------|----------|----------|----------|
| 远古守卫者 | 海底神殿 | 水下分支研究站彩蛋 | ❌ 可选支线 |
| 劫掠兽 | 灾厄村民 raid | 灾厄村民分支研究禁忌生命合成 | ❌ 可选支线 |
| 唤魔者 | 林地府邸 | 灾厄村民隐修地 | ❌ 可选支线 |

### 4.3 凋灵与监守者的主线必要性论证

**凋灵为什么必经**：
- 凋灵之灾是模组三大灾变之一（[`02-story-timeline-plan`](./02-story-timeline-plan.md) §5.2）
- 玩家通过收集凋灵骷髅头颅+召唤凋灵，亲身体验先民灾变的余响
- 击败凋灵后触发 tellraw："你重现了他们的实验，并活了下来"（[`07-boss-narrative-binding`](./07-boss-narrative-binding.md) §3.1）
- 凋灵骷髅头颅本身是模组叙事的载体（先民射手阶层转化体）

**监守者为什么必经**：
- 幽匿之厄是模组三大灾变之一（[`02-story-timeline-plan`](./02-story-timeline-plan.md) §5.3）
- 玩家在远古城市必须接触监守者（无论击杀或避开）
- 玩家若击杀监守者触发 tellraw："幽厄之灾的悲剧，在你手中结束"
- 监守者掉落的"回响碎片"是合成唱片 5 的关键（原版机制）

### 4.4 结论

**主线 Boss 必经清单**：
1. **凋灵**（玩家主动召唤）—— 阶段 4
2. **监守者**（玩家意外遭遇，可击杀或避开）—— 阶段 5
3. **末影龙**（玩家主动挑战）—— 阶段 7

## 5. Q14 · 剧情顺序简聊

### 5.1 协作者简聊

按 [`02-story-timeline-plan.md`](./02-story-timeline-plan.md) 六大纪元 + [`03-player-journey-map.md`](./03-player-journey-map.md) 十阶段，剧情顺序可简聊如下：

#### 故事内部时序（开发者视角）

```
鼎盛纪元：先民文明兴起
  ├ 掌握维度穿行技术
  ├ 三界开拓（主世界/下界/末地）
  ├ 四大研究领域并行（维度穿行/红石机械/灵魂能量/生命本源）
  └ 建造鼎盛期建筑（要塞/废弃矿井/沙漠神殿/丛林神庙/试炼密室/末地城）

凋灵之灾：第一次失控
  ├ 灵魂能量研究延伸下界
  ├ 凋灵召唤实验失控
  ├ 灵魂扭曲波席卷下界
  ├ 善魂被污染为恶魂，凋灵骷髅诞生
  └ 先民撤回主世界

幽匿之厄：第二次失控
  ├ 撤回主世界后集中研究幽匿
  ├ 幽匿实验失控
  ├ 监守者诞生（科研贵族灵魂聚合体）
  └ 远古城市封印

苍白之悔：第三次失控
  ├ 退守苍白花园研究生命本源
  ├ 生命树脂实验失控
  ├ 嘎枝诞生（防御程序回响）
  └ 苍白花园白化

大分裂：文明崩解
  ├ 三界据点荒废
  └ 族群各自演化
      ├ 主世界：村民+流浪商人（保留古法但失忆）
      ├ 主世界黑森林：灾厄村民（拒绝接受失败，研究禁忌生命合成）
      ├ 主世界地下：骷髅+流髑+Bogged（灵魂被困执行最后命令）
      ├ 下界：猪灵+僵尸猪灵（环境变异部分开智）
      └ 末地：末影人（维度异化记忆残缺）

现代纪元：玩家进入故事
  ├ 玩家出生（局外人）
  ├ 主世界考古 → 拼凑先民存在
  ├ 下界探索 → 目睹凋灵之灾余波
  ├ 远古城市+苍白花园 → 目睹灾变遗址
  ├ 进入末地 → 击败末影龙 → End Poem
  ├ 末地城/末地船 → 发现殖民军真相
  ├ 收集全部 22 张唱片 → 合成 0 号唱片
  └ 真结局：M. 遗言 → 玩家觉醒为继承者
```

#### 玩家探索顺序（按 22 文档 §5 已确认修订版）

1. **出生**：玩家随机出生，模组不干预
2. **自由探索期**：玩家挖矿/采集/建造/生存
3. **拾取笔记 #1**（落款 M.）：在任一原版结构 loot 中触发

6. **进入下界**：建造传送门 → 下界要塞（#19）→ 堡垒遗迹（#11/#12/#22）
7. **回主世界**
8. **远古城市**（#14）：深暗之域 → 幽匿之厄叙事
9. **苍白花园**（#18）：黑暗森林 → 苍白之悔叙事
10. **要塞图书馆**（#13/#17）：寻找末地传送门

13. **末地城/末地船**（#23/#24）：通过折跃门进入外岛
14. **终界岛**（#25）：维度穿行技术报告

## 6. Q15 · 模组可以计划支持多语言吗？

### 6.1 协作者回答

✅ **已规划**。详见 [`11-localization-strategy.md`](./11-localization-strategy.md)。

### 6.2 多语言策略速查

| 阶段 | 语言覆盖 | 状态 |
|------|----------|------|
| v0.1 ~ v0.5 | zh_cn（中文）+ en_us（英文） | 双源同步，互为校对 |
| v0.5 | + ja_jp（日文，Minecraft 重要市场） | 项目方亲译 |
| v0.6 ~ v0.9 | + ko_kr（韩文）+ de_de（德文）+ fr_fr（法文）+ ru_ru（俄文）+ es_es（西班牙文） | 社区贡献 PR，项目方审核 |
| v1.0 | 8 语言全覆盖 | 正式发布 |

### 6.3 实现方式（L1 主导）

- **L1**（~95%）：用原版 `assets/remnant/lang/{lang}.json` + Patchouli 多语言目录
- **L3**（~5%）：仅当原版字体在 Patchouli 中渲染缺失时，启用内嵌 Noto Sans SC 字体（v0.5 实测后决定）

### 6.4 翻译流程

- zh_cn + en_us 由项目方亲笔，互为校对
- 其他语言通过 GitHub PR 提交，项目方审核
- **不接受机器翻译**作为最终交付
- PR 必须附术语对应表与翻译思路说明

### 6.5 字符串 key 命名规范

```
物品：item.remnant.tattered_note / item.remnant.music_disc_0.desc
advancement：advancements.remnant.lore.chapter_0.title / .description
tellraw：remnant.message.cognitive_lock.not_ready
lore 章节：remnant.lore.chapter_X.page_Y / .title / .subtitle
```

所有 key 必须以 `remnant.` 前缀，避免与原版 `minecraft.` 冲突。

## 7. Q16 · 是否使用预渲染视频？还是借鉴录制类模组的代码？

### 7.1 项目方问题

> "针对部分剧情，是否使用预渲染视频？还是借鉴录制类模组的代码来录制动作与视角？"

### 7.2 协作者回答

**❌ 不使用预渲染视频**
**❌ 不借鉴录制类模组代码（如 Replay Mod）**
**✅ 通过原版 advancement + tellraw + particle + /playsound 实现电影感叙事**

### 7.3 论证

#### 预渲染视频不可行的原因

| 维度 | 评估 |
|------|------|
| 与原则 0 冲突 | 预渲染视频是"新机制"，原版无对应实现——属 L3 自定义，但违反"永远禁止"清单的"新机制" |
| 与原则 3 冲突 | 预渲染视频是"过场播片"，违反"不出现对话/过场/引导箭头" |
| 玩家体验 | 预渲染视频剥夺玩家控制，破坏原版自由探索感 |
| 工作量 | 预渲染视频需要专业动画师+剪辑师，工作量极大 |
| 文件体积 | 视频文件会让模组体积膨胀，影响下载与安装 |

#### 录制类模组代码不可行的原因

| 维度 | 评估 |
|------|------|
| 与原则 0 冲突 | 录制回放是"新机制"，原版无对应实现 |
| 与原则 3 冲突 | 录制回放仍是"过场播片"的变种 |
| 玩家体验 | 玩家被迫观看预录的动作，无法自主决策 |

#### 替代方案：电影化碎片叙事

通过原版机制实现"电影感"而不剥夺玩家控制：

| 维度 | 实现方式 | L 等级 |
|------|----------|--------|
| **叙事文本** | 通过 `tellraw` 在关键时刻显示多段叙事文本（如击败末影龙后立即显示守门人真相） | L1 |
| **氛围粒子** | 通过 `/particle` 命令在关键场景显示氛围粒子（如远古城市的 dragon_breath 黑雾） | L1 |
| **配乐时机** | 通过 `/playsound` 在关键节点播放对应原版曲目（详见 23 文档 §4） | L1 |
| **光线变化** | 通过原版 `/time set` 或 `/weather` 在关键场景调整时间与天气（如苍白花园的永恒黄昏） | L1 |
| **多重 tellraw 同步** | 通过 function 同时调用多个 tellraw，形成"分段叙事"效果（类似电影对白节奏） | L2 |
| **advancement 链式触发** | 通过 advancement reward function 链式调用，形成"叙事爆发"（如拾取笔记 #26 后立即触发 0 号唱片合成 advancement + End Poem 重新解读 tellraw） | L2 |

### 7.4 妥协方案：若项目方坚持要更强电影感

若项目方认为 L1+L2 的电影感不足，可考虑 **L3 自定义"剧场方块"** 作为彩蛋：

| 候选 | 描述 | L 等级 | 必要性论证 | 关联性论证 |
|------|------|--------|------------|------------|
| **叙事讲台（Lecture Stand）** | 自定义方块，玩家右键触发时按预设节奏显示多段 tellraw+particle+playsound，类似 Patchouli 章节但更电影化 | L3 | L1+L2 的散点叙事在关键节点（如真结局前）缺乏集中爆发；Patchouli 章节是静态文本，缺乏节奏感 | 视觉关联（材质基于原版讲台 lectern 衍生）+ 行为关联（右键交互与原版讲台一致）+ 退化关联（失去模组后退化为原版 lectern，仍可放书阅读） |

**结论**：
- v0.1 ~ v0.5：仅实施 L1+L2 电影化碎片叙事
- v0.6 真结局开发时：评估是否启用 L3 自定义"叙事讲台"作为真结局前的集中爆发
- ❌ 永远不使用预渲染视频或录制回放

## 8. Q17 · 进入世界前是否提示"打开光影后游戏效果会更好"？

### 8.1 项目方问题

> "进入世界前是否提示'打开光影后游戏效果会更好。'？"

### 8.2 协作者回答

**✅ 可以提示，但需遵守以下约束**：

1. **不强制**：提示只出现一次，玩家可关闭
2. **不内置光影**：按 [`22-design-questions-answers.md`](./22-design-questions-answers.md) §Q10-b 已明确"不内置光影"
3. **不指定特定光影包**：仅推荐"使用光影"，不指定 OptiFine/Iris/Continuity 等具体包
4. **L1 实现**：通过原版 advancement 在玩家首次进入世界时显示一次性提示

### 8.3 实现方案

**advancement 配置**：

```json
// data/remnant/advancement/intro/shader_recommendation.json
{
  "display": {
    "icon": { "item": "minecraft:sunflower" },
    "title": "欢迎使用 Remnant Echo",
    "description": "建议启用光影以获得最佳沉浸体验（可选）",
    "show_toast": true,
    "announce_to_chat": false,
    "hidden": false,
    "frame": "task"
  },
  "criteria": {
    "enter_world": {
      "trigger": "minecraft:location",
      "conditions": {
        "player": {
          "location": {
            "dimension": "minecraft:overworld"
          }
        }
      }
    }
  },
  "rewards": {
    "function": "remnant:intro/shader_recommendation_message"
  }
}
```

**触发 function**：

```mcfunction
# data/remnant/functions/intro/shader_recommendation_message.mcfunction
tellraw @s {"text":"======================================","color":"gray"}
tellraw @s {"text":"欢迎使用 Remnant Echo","color":"gold","bold":true}
tellraw @s {"text":"======================================","color":"gray"}
tellraw @s {"text":"","extra":[{"text":"建议启用光影以获得最佳沉浸体验（如 Iris Shaders / OptiFine）。","color":"aqua"},{"text":"非必需，模组在原版渲染下仍可完整体验。","color":"dark_gray"}]}
tellraw @s {"text":"======================================","color":"gray"}
```

### 8.4 多语言支持

按 [`11-localization-strategy.md`](./11-localization-strategy.md)，此提示在 v0.1 即支持 zh_cn + en_us 双语：

```json
// assets/remnant/lang/zh_cn.json
{
  "remnant.message.intro.shader_recommendation.title": "欢迎使用 Remnant Echo",
  "remnant.message.intro.shader_recommendation.body": "建议启用光影以获得最佳沉浸体验（如 Iris Shaders / OptiFine）。非必需，模组在原版渲染下仍可完整体验。"
}
```

### 8.5 玩家可关闭

通过模组配置文件（`config/remnant.toml`）允许玩家关闭此提示：

```toml
# config/remnant.toml
[intro]
show_shader_recommendation = true  # 玩家可设为 false 关闭
```

### 9.4 L3 自定义粒子论证

按 [原则 0 · L3 自定义的关联性标准](./00-planning-index.md#l3-自定义的关联性标准)，所有 L3 自定义粒子需通过论证：

| 候选粒子 | 必要性论证 | 关联性论证 | 退化方案 |
|---------|------------|------------|----------|
| **`withering_wave`**（凋零波，红紫色） | L1：原版 `large_smoke` 是黑色，无法承载"灵魂扭曲波"的紫色能量感；L2：组合也无法表达 | 视觉关联（基于原版 `large_smoke` 形状+紫色色变）+ 场景关联（仅凋灵召唤时触发） | 失去模组时退化为原版 `large_smoke` |
| **`sculk_echo`**（幽匿回响，紫色） | L1：原版 `sculk_soul` 是蓝色，无法承载"幽匿侵蚀"的紫色感；L2：组合也无法表达 | 视觉关联（基于原版 `sculk_soul` 形状+紫色色变）+ 场景关联（仅监守者附近触发） | 失去模组时退化为原版 `sculk_soul` |
| **`pale_regret`**（苍白化，白色） | L1：原版 `white_ash` 是白色但随机散落，无法承载"白化侵蚀"的定向感；L2：组合也无法表达 | 视觉关联（基于原版 `white_ash` 形状）+ 场景关联（仅苍白花园触发） | 失去模组时退化为原版 `white_ash` |
| **`colonial_echo`**（殖民回响，紫蓝色） | L1：原版 `end_rod` 是白色，无法承载"殖民军余响"的紫蓝色感；L2：组合也无法表达 | 视觉关联（基于原版 `end_rod` 形状+紫蓝色变）+ 场景关联（仅末地城触发） | 失去模组时退化为原版 `end_rod` |
| **`m_farewell`**（M. 告别，金蓝色） | L1：原版无任何粒子能承载"M. 灵魂告别"的庄重感；L2：组合也无法表达 | 视觉关联（基于原版 `end_rod`+`enchant` 衍生）+ 场景关联（仅 0 号唱片播放时触发） | 失去模组时退化为原版 `end_rod` |
