# 01 · 玩家出生点叙事设计

> **状态**：🟡 设计讨论中
> **对应模组版本**：v0.1（概念验证）
> **创建日期**：2026-09-18
> **最后更新**：2026-09-18
> **设计原则**：[补不是添](./00-planning-index.md#原则-0补不是添)

---

## 1. 设计目标

玩家创建世界并第一次进入时，必须满足：

1. **叙事种子埋下**：玩家在第一次游戏会话中接触到第一条故事线索
2. **完全不破坏原版体验**：保留 Minecraft 原版的随机出生、自由探索感
3. **不魔改原版交互**：不新增自定义物品、方块、机制
4. **三界同源伏笔**：第一份线索应能引出"远古先民文明"的存在

---

## 2. 核心矛盾与解决思路

Minecraft 原版出生逻辑完全随机，玩家可能落在沙漠、海洋、雪原、丛林等无村庄群系，叙事第一环可能断裂。

**解决思路**：不通过强制生成结构保证叙事种子，而是通过**原版 loot 表扩展**让玩家在**自然探索过程中**自然遇到第一条线索。

**关键决策**：放弃"保证第一次会话必触发叙事"的目标。玩家可能在第一次游戏会话中未触发叙事，但只要继续探索，终会触发。这符合"碎片化叙事"原则——叙事不是任务，是探索的副产品。

---

## 3. 备选方案对比

### 方案 A：纯原版 loot 表扩展（推荐 ✅）

**做法**：向原版结构的 loot 表中追加 `written_book` 物品条目。

| 维度 | 评价 |
|------|------|
| 原版兼容性 | ★★★★★ 完全保留，不改变任何结构生成 |
| 叙事种子可靠性 | ★★★☆☆ 玩家探索到任意含 loot 的原版结构时即可触发 |
| 实现复杂度 | ★☆☆☆☆ 仅需修改 loot 表 JSON |
| 是否符合"补不是添" | ✅ 完全符合，仅"补"原版 loot 表，不"添"新结构 |
| **结论** | ✅ 采用为主方案 |

**追加 loot 表的目标结构**：
- 村庄图书馆箱子（最常见的玩家早期接触结构）
- 沙漠神殿箱子
- 丛林神庙箱子
- 废弃矿井矿车箱子
- 地牢箱子（dungeon）

### 方案 B：软引导村庄生成（不采用 ❌）

**做法**：出生点 128 格内强制生成村庄，村庄中必含考古棚。

| 维度 | 评价 |
|------|------|
| 是否符合"补不是添" | ❌ 违反，强制生成村庄 + 新增考古棚结构属于"添" |
| **结论** | ❌ 不采用 |

### 方案 C：自定义祭坛出生点（不采用 ❌）

**做法**：出生点正下方生成自定义"先民储藏室"。

| 维度 | 评价 |
|------|------|
| 是否符合"补不是添" | ❌ 违反，新增自定义结构 |
| **结论** | ❌ 不采用 |

### 方案 D：维度穿越式开场（不采用 ❌）

| 维度 | 评价 |
|------|------|
| 是否符合"补不是添" | ❌ 严重违反，改变出生逻辑 |
| **结论** | ❌ 不采用 |

## 4. 推荐方案：A · 原版 loot 表扩展

### 4.1 设计要点

1. **零结构修改**：不新增任何结构，不改变出生点逻辑
2. **零物品修改**：不新增自定义物品，叙事文本全部承载于原版 `written_book`
3. **零机制修改**：不新增触发器，通过原版 `loot_table` 与 `advancement` 实现
4. **碎片化触发**：玩家在任何含 loot 的原版结构中可能发现叙事文本

### 4.2 第一份叙事文本的承载方式

**物品**：原版 `written_book`

**NBT 结构**：
```nbt
{
  display: {
    Title: "残破的笔记",  // 用原版 Title 字段显示标题
    Lore: ["纸张泛黄，墨迹模糊"]
  },
  CustomModelData: 0,  // 不使用自定义模型，外观为原版书本
  pages: [
    '{"text":"寻找那座塔。它会告诉你我们是谁。\\n\\n不要相信猪灵。也不要相信我们。\\n\\n—— M."}'
  ],
  author: "M.",
  title: "残破的笔记",
  resolved: 1b
}
```

**视觉表现**：与原版 `written_book` 完全一致，无自定义纹理、无自定义模型。玩家右键打开后看到叙事文本。

### 4.3 loot 表追加条目

向原版结构 loot 表中追加 `written_book` 条目。

**示例：村庄图书馆箱子**（`data/minecraft/loot_table/chests/village/village_library.json` 修改）：

```json
{
  "pools": [
    // ... 原有 pools 保留 ...
    {
      "rolls": 1,
      "entries": [
        {
          "type": "minecraft:item",
          "name": "minecraft:written_book",
          "weight": 5,
          "quality": 2,
          "functions": [
            {
              "function": "minecraft:set_nbt",
              "tag": "{display:{Title:\"残破的笔记\",Lore:[\"纸张泛黄，墨迹模糊\"]},pages:[\"{\\\"text\\\":\\\"寻找那座塔。它会告诉你我们是谁。\\\\n\\\\n不要相信猪灵。也不要相信我们。\\\\n\\\\n—— M.\\\"}\"],author:\"M.\",title:\"残破的笔记\",resolved:1b}"
            }
          ]
        }
      ],
      "conditions": [
        {
          "condition": "minecraft:random_chance",
          "chance": 0.15
        }
      ]
    }
  ]
}
```

**追加 loot 表的目标结构列表**：

| 原版结构 | loot 表路径 | 触发概率 | 叙事文本 |
|----------|-------------|----------|----------|
| 村庄图书馆箱子 | `chests/village/village_library` | 15% | 笔记 #1：寻找那座塔 |
| 沙漠神殿箱子 | `chests/desert_pyramid` | 10% | 笔记 #2：祭祀记录 |
| 丛林神庙箱子 | `chests/jungle_temple` | 10% | 笔记 #3：红石记录 |
| 废弃矿井矿车 | `chests/abandoned_mineshaft` | 8% | 笔记 #4：劳工日志 |
| 地牢箱子 | `chests/simple_dungeon` | 12% | 笔记 #5：监禁记录 |

**设计原则**：
- 多份笔记分布在多个原版结构中，玩家任意找到一个即可触发叙事
- 不同笔记内容不同，但都暗示"远古先民文明"的存在
- 玩家可以**只读一份笔记就开始探索**，也可以**收集全部笔记拼凑完整故事**

### 4.4 笔记触发线索书章节解锁

**机制**：基于原版 `advancement` 触发器

**实现**：
```json
// data/remnant/advancement/lore/find_first_note.json
{
  "criteria": {
    "find_note_1": {
      "trigger": "minecraft:inventory_changed",
      "conditions": {
        "items": [
          {
            "items": ["minecraft:written_book"],
            "nbt": "{display:{Title:\"残破的笔记\"}}"
          }
        ]
      }
    }
  },
  "rewards": {
    "function": "remnant:lore/unlock_chapter_0"
  }
}
```

**解锁效果**：
- 触发 `remnant:lore/unlock_chapter_0` 函数
- 该函数通过 `tellraw` 显示「线索书第 0 章已解锁」提示
- 同时调用 `advancement` revoke 机制避免重复触发

### 4.5 与原版的兼容性验证

| 检查项 | 状态 |
|--------|------|
| 玩家出生点是否被改变？ | ❌ 不改变 |
| 玩家是否被强制传送？ | ❌ 不传送 |
| 玩家是否被强制播放对话？ | ❌ 不播放 |
| 玩家是否被阻止自由探索？ | ❌ 不阻止 |
| 是否新增可驯服/骑乘机制？ | ❌ 不新增 |
| 是否改变生物 AI/掉落？ | ❌ 不改变 |
| 是否改变村庄本身的生成？ | ❌ 不改变 |
| 是否新增自定义物品？ | ❌ 不新增（用原版 written_book） |
| 是否新增自定义方块？ | ❌ 不新增 |
| 是否新增自定义机制？ | ❌ 不新增（用原版 advancement） |
| 是否修改原版 loot 表？ | ✅ 仅追加条目，不删除原有内容 |

**结论**：方案 A 完全符合"补不是添"原则。

## 5. 第一份残破笔记的内容候选

按"碎片化叙事"原则，第一句**不能太直白**，应该埋钩子，激发玩家好奇心并暗示后续探索方向。

### 5.1 候选开场白

| 编号 | 内容 | 风格 | 暗示方向 |
|------|------|------|----------|
| 1 | 「我们曾掌握三界的钥匙，如今只剩下这把锁。」 | 先民视角、悲怆 | 三界同源、维度穿行技术 |
| 2 | 「当他们离开时，把这些留下了。」 | 中立叙述、谜题感 | 先民的存在与消失 |
| 3 | 「寻找那座塔。它会告诉你我们是谁。」 | 指引型、神秘 | 要塞（要塞有塔楼结构） |
| 4 | 「不要相信猪灵。也不要相信我们。」 | 误导型、种族不信任 | 猪灵分支、先民原罪 |
| 5 | 「记忆比石头更脆弱。挖深一点，你会看到的。」 | 双关、指向地下 | 废弃矿井、远古城市 |

### 5.2 推荐组合：3 + 4

笔记正文（草稿）：

> 「寻找那座塔。它会告诉你我们是谁。
>
> 不要相信猪灵。也不要相信我们。
>
> —— M.」

**理由**：
- 第 1 句给出探索方向（要塞 → 末地传送门），避免玩家漫无目的
- 第 2 句埋下种族不信任伏笔（猪灵分支、先民原罪），呼应"灾变与分裂"设定
- 落款 "M." 是神秘符号，可后续在末地城日记中揭晓身份（先民领袖？末地殖民军指挥官？）

### 5.3 五份笔记的内容设计（多份笔记分散触发）

| 笔记编号 | 出处结构 | 内容主题 | 暗示方向 |
|----------|----------|----------|----------|
| 1 | 村庄图书馆 | 寻找那座塔 | 要塞 |
| 2 | 沙漠神殿 | 祭祀信仰 | 先民信仰体系 |
| 3 | 丛林神庙 | 红石机械 | 红石研究领域 |
| 4 | 废弃矿井 | 劳工日志 | 劳工阶层、地下交通 |
| 5 | 地牢 | 监禁记录 | 监禁/储存设施 |

每份笔记独立可读，但读完所有 5 份后通过 `advancement` 触发线索书第 1 章「先民存在」解锁。

## 6. 触发逻辑

### 6.1 玩家进入世界时的触发流程

```
玩家创建世界
    ↓
进入世界（出生点随机生成，模组不干预）
    ↓
玩家自由探索
    ↓
玩家发现任意原版结构（村庄图书馆 / 沙漠神殿 / 丛林神庙 / 废弃矿井 / 地牢）
    ↓
玩家开启结构内的箱子
    ↓
箱子的 loot 表按设定概率生成「残破的笔记」(written_book)
    ↓
玩家右键使用 written_book → 阅读叙事文本
    ↓
玩家背包中存在该 written_book 时触发 advancement
    ↓
advancement 触发 function → tellraw 提示「线索书第 0 章已解锁」
    ↓
玩家可继续探索其他结构，收集全部 5 份笔记
    ↓
收集全部 5 份笔记 → 触发线索书第 1 章「先民存在」解锁
```

### 6.2 不强制第一次会话触发

**设计取舍**：
- 玩家可能在第一次游戏会话中未触发叙事（如果没找到任何含 loot 的结构）
- 这是**可接受**的，因为：
  1. 符合"碎片化叙事"原则——叙事不是任务，是探索的副产品
  2. 玩家继续游戏终会触发（minecraft 早期游戏必然接触村庄或地牢）
  3. 强行保证第一次会话触发会违反"补不是添"原则

- [ ] 创建新世界，玩家在主世界随机出生

- [ ] 不改变任何原版结构生成逻辑
- [ ] 不新增任何自定义物品、方块、机制

## 8. 风险与讨论点

### 8.1 风险

1. **玩家可能长期不接触含 loot 的结构**
   - 缓解：在 5 种最常见的早期结构中分布笔记，玩家接触任一即可触发
   - 接受：符合"碎片化叙事"原则，不强制触发

2. **玩家可能丢弃笔记，导致 advancement 不触发**
   - 缓解：advancement 触发条件为 `inventory_changed`，玩家拾取即触发，无需保留
   - 即使丢弃，已触发的 advancement 不会撤销

3. **多人服务器中，多个玩家共享箱子**
   - 缓解：每个玩家独立判定 advancement
   - 第一个开箱的玩家获得笔记（原版 loot 机制），其他玩家可能错过
   - 缓解：可通过 `/loot` 命令重新生成，或调整 loot 表概率使多人游戏时概率提升

### 8.2 待讨论的设计问题

- [ ] 笔记是否使用 `CustomModelData` 改变外观？（建议否，保持原版书本外观）
- [ ] 笔记是否灵魂绑定防止丢弃？（建议否，违反"不魔改原版交互"）
- [ ] 笔记内容是否本地化为多语言？（建议是，通过 `lang/` JSON 实现，不引入新机制）
- [ ] 落款 "M." 的身份设定？建议预留至末地线揭晓（先民领袖/末地殖民军指挥官）
- [ ] Patchouli 模组作为软依赖是否可接受？（建议是，Patchouli 是社区标准，非"新机制"）
