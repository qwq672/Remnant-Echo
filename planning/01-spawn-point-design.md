# 01 · 玩家出生点叙事设计

> **状态**：🟡 设计讨论中
> **对应模组版本**：v0.1（概念验证）
> **创建日期**：2026-09-18
> **最后更新**：2026-09-18
> **设计原则**：[补优先于添](./00-planning-index.md#原则-0补优先于添) · [以原版世界观为主](./00-planning-index.md#原则-1以原版世界观为主)

---

## 1. 设计目标

玩家创建世界并第一次进入时，必须满足：

1. **叙事种子埋下**：玩家在第一次游戏会话中接触到第一条故事线索
2. **不破坏原版体验**：保留 Minecraft 原版的随机出生、自由探索感
3. **不魔改原版交互**：不新增可驯服/骑乘机制，不改变生物 AI、生成、掉落
4. **三界同源伏笔**：第一份线索应能引出"远古先民文明"的存在

---

## 2. 核心矛盾与解决思路

Minecraft 原版出生逻辑完全随机，玩家可能落在沙漠、海洋、雪原、丛林等无村庄群系，叙事第一环可能断裂。

**解决思路**：通过**多层级方案组合**，既保证叙事种子的埋下，又符合「补优先于添」原则。

**关键决策**：
- **Level 1（优先）**：向原版 loot 表追加 `written_book` 条目，覆盖大多数原版结构
- **Level 2（备选）**：在原版村庄内附加少量装饰物（不新增结构，仅复用原版方块的 NBT 触发）
- **Level 3（必要时）**：自定义"先民储藏室"作为废弃矿井的结构变体，材质基于原版石砖工艺

---

## 3. 多层方案设计

### 方案 A：原版 loot 表扩展（Level 1 · 优先采用 ✅）

**做法**：向原版结构的 loot 表中追加 `written_book` 物品条目。

| 维度 | 评价 |
|------|------|
| 原版兼容性 | ★★★★★ 完全保留 |
| 实现复杂度 | ★☆☆☆☆ 仅修改 loot 表 JSON |
| 原版关联性 | ✅ 直接使用原版 `written_book`，Level 1 |
| **结论** | ✅ 作为基础方案，保证所有玩家都能触发叙事 |

**追加 loot 表的目标结构**：

| 原版结构 | loot 表路径 | 触发概率 | 叙事文本 |
|----------|-------------|----------|----------|
| 村庄图书馆箱子 | `chests/village/village_library` | 15% | 笔记 #1：寻找那座塔 |
| 沙漠神殿箱子 | `chests/desert_pyramid` | 10% | 笔记 #2：祭祀记录 |
| 丛林神庙箱子 | `chests/jungle_temple` | 10% | 笔记 #3：红石记录 |
| 废弃矿井矿车 | `chests/abandoned_mineshaft` | 8% | 笔记 #4：劳工日志 |
| 地牢箱子 | `chests/simple_dungeon` | 12% | 笔记 #5：监禁记录 |

### 方案 B：村庄图书馆附加装饰（Level 2 · 增强）

**做法**：在原版村庄图书馆内，将一个 `bookshelf` 替换为带 NBT 的特殊变体（仍为原版 `bookshelf` 方块），玩家右键时触发 `tellraw` 显示额外叙事文本。

| 维度 | 评价 |
|------|------|
| 原版兼容性 | ★★★★☆ 仅替换个别 bookshelf 的 NBT，不改变结构 |
| 实现复杂度 | ★★★☆☆ 需 Structure Processor 拦截村庄生成 |
| 原版关联性 | ✅ 用原版 `bookshelf` + 自定义 NBT 触发器，Level 2 |
| **结论** | ✅ 作为增强方案，提升村庄图书馆的叙事密度 |

**实现方式**：
- 监听村庄生成事件
- 在图书馆内寻找 `bookshelf` 方块
- 为其中 1 个 `bookshelf` 添加 NBT 标签 `{remnant: {lore_block: 1}}`
- 玩家右键该 bookshelf 时，触发 function 调用 `tellraw` 显示叙事文本

**叙事文本**（与笔记 #1 互补，不重复）：
> 「这里曾住过一位书记官。他临走时说，要去找塔。」
> —— 图书馆墙壁上的刻痕

### 方案 C：先民储藏室作为废弃矿井变体（Level 3 · 必要时）

**做法**：在原版废弃矿井生成时，有一定概率追加一个"先民储藏室"作为结构变体。

| 维度 | 评价 |
|------|------|
| 原版兼容性 | ★★★☆☆ 追加新结构变体，但材质基于原版 |
| 实现复杂度 | ★★★★☆ 需设计新结构 + WorldGen 注入 |
| 原版关联性 | ✅ 材质基于原版石砖工艺，作为原版结构变体追加，Level 3 通过 |
| **结论** | ✅ 作为彩蛋方案，提升废弃矿井的叙事价值 |

**结构设计**：
- 5×5 石砖房间（使用原版 `stone_bricks` + `mossy_stone_bricks` + `cracked_stone_bricks` 混搭）
- 1 个箱子（使用原版 `chest`，loot 表追加先民笔记 #6）
- 1 块"残破石碑"（**Level 3 自定义方块**：材质基于原版 `stone_bricks` + 雕刻纹理，行为类似 `infested_stone`——右键触发 `tellraw`）
- 1 个熄灭的灯笼（原版 `lantern`，NBT 标记为熄灭状态）
- 入口被苔石覆盖（原版 `mossy_cobblestone`）

**"残破石碑"方块设计（Level 3 自定义）**：
- 材质：基于原版 `stone_bricks` 衍生，添加类似 `chiseled_stone_bricks` 的雕刻纹理
- 行为：右键触发 function 调用 `tellraw` 显示铭文
- 硬度：与原版 `stone_bricks` 一致（1.5）
- 工具：需镐子挖掘（与原版石砖一致）
- **原版关联性**：材质基于原版石砖工艺，雕刻纹理风格参考原版 `chiseled_stone_bricks`，符合"原版关联性"标准

### 推荐方案组合：A + B + C

```
方案 A (Level 1) — 基础保证
  ↓ 保证所有玩家探索原版结构时能触发叙事
方案 B (Level 2) — 增强叙事密度
  ↓ 提升村庄图书馆的叙事价值
方案 C (Level 3) — 彩蛋提升
  ↓ 为细心探索废弃矿井的玩家提供深度叙事奖励
```

**实施优先级**：
- v0.1：仅实施方案 A（最小可用版本）
- v0.2：追加方案 B（村庄图书馆增强）
- v0.3：追加方案 C（先民储藏室彩蛋）

## 4. 第一份残破笔记的内容候选

按"碎片化叙事"原则，第一句**不能太直白**，应该埋钩子，激发玩家好奇心并暗示后续探索方向。

### 4.1 候选开场白

| 编号 | 内容 | 风格 | 暗示方向 |
|------|------|------|----------|
| 1 | 「我们曾掌握三界的钥匙，如今只剩下这把锁。」 | 先民视角、悲怆 | 三界同源、维度穿行技术 |
| 2 | 「当他们离开时，把这些留下了。」 | 中立叙述、谜题感 | 先民的存在与消失 |
| 3 | 「寻找那座塔。它会告诉你我们是谁。」 | 指引型、神秘 | 要塞（要塞有塔楼结构） |
| 4 | 「不要相信猪灵。也不要相信我们。」 | 误导型、种族不信任 | 猪灵分支、先民原罪 |
| 5 | 「记忆比石头更脆弱。挖深一点，你会看到的。」 | 双关、指向地下 | 废弃矿井、远古城市 |

### 4.2 推荐组合：3 + 4

笔记正文（草稿）：

> 「寻找那座塔。它会告诉你我们是谁。
>
> 不要相信猪灵。也不要相信我们。
>
> —— M.」

**理由**：
- 第 1 句给出探索方向（要塞 → 末地传送门），避免玩家漫无目的
- 第 2 句埋下种族不信任伏笔（猪灵分支、先民原罪），呼应"灾变与分裂"设定
- 落款 "M." 是神秘符号，可后续在末地城日记中揭晓身份（先民领袖？末地殖民军指挥官？）

### 4.3 六份笔记的内容设计（多份笔记分散触发）

| 笔记编号 | 出处结构 | 内容主题 | 暗示方向 |
|----------|----------|----------|----------|
| 1 | 村庄图书馆 / 沙漠神殿 / 丛林神庙 / 废弃矿井 / 地牢 | 寻找那座塔 | 要塞 |
| 2 | 沙漠神殿 | 祭祀信仰 | 先民信仰体系 |
| 3 | 丛林神庙 | 红石机械 | 红石研究领域 |
| 4 | 废弃矿井 | 劳工日志 | 劳工阶层、地下交通 |
| 5 | 地牢 | 监禁记录 | 监禁/储存设施 |
| 6 | 先民储藏室（方案 C） | 储藏清单 | 物资储备、撤离迹象 |

每份笔记独立可读，但读完所有 6 份后通过 `advancement` 触发线索书第 1 章「先民存在」解锁。

## 5. 触发逻辑

### 5.1 玩家进入世界时的触发流程

```
玩家创建世界
    ↓
进入世界（出生点随机生成，模组不干预）
    ↓
玩家自由探索
    ↓
玩家发现任意原版结构（村庄图书馆 / 沙漠神殿 / 丛林神庙 / 废弃矿井 / 地牢）
    ↓
玩家开启结构内的箱子
    ↓
箱子的 loot 表按设定概率生成「残破的笔记」(written_book) — 方案 A
    ↓
玩家右键使用 written_book → 阅读叙事文本
    ↓
玩家背包中存在该 written_book 时触发 advancement
    ↓
advancement 触发 function → tellraw 提示「线索书第 0 章已解锁」
    ↓
玩家可继续探索其他结构，收集全部 6 份笔记
    ↓
收集全部 6 份笔记 → 触发线索书第 1 章「先民存在」解锁
    ↓
（可选彩蛋）玩家在废弃矿井中发现先民储藏室 → 右键残破石碑触发额外铭文 — 方案 C
```

### 5.2 不强制第一次会话触发

**设计取舍**：
- 玩家可能在第一次游戏会话中未触发叙事（如果没找到任何含 loot 的结构）
- 这是**可接受**的，因为：
  1. 符合"碎片化叙事"原则——叙事不是任务，是探索的副产品
  2. 玩家继续游戏终会触发（minecraft 早期游戏必然接触村庄或地牢）
  3. 强行保证第一次会话触发会违反"补优先于添"原则

## 6. 实现路径

### 6.1 v0.1 验收标准（仅方案 A）

- [ ] 创建新世界，玩家在主世界随机出生
- [ ] 玩家自由探索，发现任意原版结构
- [ ] 结构内的箱子按设定概率生成「残破的笔记」(written_book)
- [ ] 玩家右键阅读笔记，看到叙事文本
- [ ] 笔记进入背包后触发 advancement，显示线索书第 0 章解锁提示
- [ ] 多次创建世界测试，每次都能在合理时间内（数小时内）触发叙事种子
- [ ] 不改变任何原版结构生成逻辑
- [ ] 不新增任何自定义物品、方块、机制

### 6.2 v0.2 验收标准（追加方案 B）

- [ ] 村庄图书馆生成时，有概率将 1 个 `bookshelf` 替换为带 NBT 的变体
- [ ] 玩家右键该 bookshelf 时触发 `tellraw` 显示叙事文本
- [ ] 文本与笔记 #1 互补，不重复
- [ ] 不破坏原版村庄结构，仅替换个别方块的 NBT

### 6.3 v0.3 验收标准（追加方案 C）

- [ ] 自定义"先民储藏室"结构作为废弃矿井的变体追加生成
- [ ] 结构使用原版石砖材质 + 苔石工艺
- [ ] 结构内包含"残破石碑"方块（Level 3 自定义，材质基于原版石砖衍生）
- [ ] 玩家右键"残破石碑"触发 `tellraw` 显示铭文
- [ ] 玩家挖掘"残破石碑"获得原版 `stone_bricks`（不新增自定义物品掉落）
- [ ] 结构生成概率低（如 5% 的废弃矿井），作为彩蛋
- [ ] 不破坏废弃矿井的原版生成逻辑，仅追加变体

## 7. 风险与讨论点

### 7.1 风险

1. **玩家可能长期不接触含 loot 的结构**
   - 缓解：在 5 种最常见的早期结构中分布笔记，玩家接触任一即可触发
   - 接受：符合"碎片化叙事"原则，不强制触发

2. **方案 B 的村庄图书馆 NBT 替换可能与原版冲突**
   - 缓解：仅替换 1 个 `bookshelf`，保留其他原版生成
   - 缓解：通过 Structure Processor 在生成时拦截，不修改原版村庄结构文件

3. **方案 C 的先民储藏室可能与废弃矿井冲突**
   - 缓解：作为变体追加，仅 5% 概率生成
   - 缓解：使用原版石砖材质，与废弃矿井的木板/栅栏风格一致

4. **多人服务器中，多个玩家共享箱子**
   - 缓解：每个玩家独立判定 advancement
   - 第一个开箱的玩家获得笔记（原版 loot 机制），其他玩家可能错过
   - 缓解：可通过 `/loot` 命令重新生成，或调整 loot 表概率使多人游戏时概率提升

### 7.2 待讨论的设计问题

- [ ] 笔记是否使用 `CustomModelData` 改变外观？
  - 倾向：可使用 `CustomModelData` 改变 `written_book` 外观为泛黄卷边，但材质基于原版书页纹理衍生（符合 Level 3「原版关联性」）
- [ ] 笔记是否灵魂绑定防止丢弃？
  - 倾向：否，违反"不魔改原版交互"
- [ ] 笔记内容是否本地化为多语言？
  - 倾向：是，通过 `lang/` JSON 实现
- [ ] 落款 "M." 的身份设定？
  - 倾向：预留至末地线揭晓（先民领袖/末地殖民军指挥官）
- [ ] 方案 C 的"残破石碑"是否过于"添"？
  - 倾向：材质基于原版石砖衍生，雕刻纹理参考原版 `chiseled_stone_bricks`，符合 Level 3 标准
- [ ] Patchouli 模组作为软依赖是否可接受？
  - 倾向：是，Patchouli 是社区标准，非"新机制"
